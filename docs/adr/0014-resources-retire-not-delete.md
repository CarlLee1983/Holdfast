# 資源只停用、不刪除

資源不再提供時，管理者把它停用（見 `CONTEXT.md` 的「停用」），而不是刪除。一個跑過一陣子的資源底下必有時段與訂位歷史，含已取消的訂位；刪除資源等於連帶抹掉這些歷史，或者因為外鍵而永遠刪不掉。停用只擋新的保留與新時段，既有的保留照 [ADR 0003](0003-confirm-judged-by-time.md) 只看時間判定能否確認，不多加「資源是否停用」的條件。

**Considered Options:** 只有在資源底下沒有任何時段時才能刪除——現實中幾乎永遠刪不掉，等於沒有這個功能；連同時段與訂位一併刪除——抹掉訂位歷史，與 [ADR 0012](0012-slot-delete-discards-inactive-holds.md) 保護歷史的立場相反；停用與刪除都做——多一條很少走、卻會毀損資料的路徑。

**Consequences:** 資源多一個停用狀態，每個會員面讀取資源與時段的查詢都要排除停用的資源；後台仍列出停用的資源，並可重新啟用。停用的資源永遠占著一列，列表因此只增不減，這個代價被接受。之後若有人想加「刪除資源」，應先推翻這份 ADR。

**Falsified if:** `apps/app/src/catalog/schema.ts` 出現刪除資源的路徑，或訂位歷史改存到不依賴資源列的地方，使刪除資源不再會抹掉歷史。
